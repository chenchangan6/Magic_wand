# 灯效库与协议记录

这份记录只描述当前本地端的灯效库 schema 和后续协议约定，不代表接收端已实现。

## 现状

- 灯效库是用户可编辑的预设库，可以无限新增。
- 每个灯效预设最多启用 3 路轨道。
- 每一路轨道可选择 `LED1` 到 `LED4` 中的一路。
- `自检` 不是灯效库项目，它属于接收端功能/调试能力。

## 灯效预设 schema

每个灯效预设使用 `effect_ui.schema = 2`，核心结构如下：

- `mode`: 主模式，示例值：
  - `silent`
  - `solid`
  - `breath`
  - `blink`
  - `cycle`
  - `chase`
  - `pulse_chase`
- `tracks[]`: 轨道数组，最多 3 项

每条轨道建议包含这些字段：

- `enabled`: 是否启用
- `port`: 1-4，对应 LED1-LED4
- `mode`: 单轨模式
- `led_count`: 灯珠总数，例如 35、90
- `led_start`: 起始灯号，默认 1
- `led_end`: 结束灯号
- `gap`: 灯珠间隔，例如 2 表示 1、4、7、10
- `brightness`: 亮度百分比
- `colors[]`: 颜色列表，通常 1-3 个颜色
- `repeat`: 重复次数，例如呼吸次数、脉冲次数
- `frequency_hz`: 频率，单位是次/秒
- `period_ms`: 周期，单位毫秒
- `duty`: 占空比百分比
- `accel`: 加速度，脉冲跑马可用
- `end_hold_ms`: 结束后停留多久
- `end_behavior`: 结束动作，建议值 `off` / `hold` / `loop`

## 设计约定

- 本地端负责保存和编辑灯效预设。
- 发布到控制端时，本地端会把 `effects` 一起带上。
- 控制端再把灯效定义转发给接收端。
- 接收端只需要理解自己能执行的模式和参数，不需要知道本地端的编辑界面。

## 未来接收端实现提示

- `breath`：支持颜色渐变、占空比、频率、间隔灯珠。
- `blink`：支持周期与占空比。
- `cycle`：支持多色轮转。
- `chase`：支持范围、间隔、方向、速度。
- `pulse_chase`：跑马灯变体，支持加速度、结束停留、最后熄灭。
- 设备资源紧张时，最多只允许 3 路同时点亮。
