# Magic Wand 玩法开局与验收手册

版本：2026-06-04  
适用范围：本地端玩法预设、房间开局、控制端下发、接收端自主判定。

## 一、先理解系统怎么跑

Magic Wand 的现场链路是：

1. 本地端配置玩法预设、房间、设备分组、灯效和本局覆盖参数。
2. 设备预备时，本地端把精简运行配置发布给控制端。
3. 控制端只负责把规则、灯效、配对、START/STOP 下发给接收端，并汇总事件。
4. 开始游戏后，接收端之间用 ESP-NOW beacon 和 RSSI 自主判定。
5. 接收端触发成功后上报事件，控制端写入状态，本地端大屏显示积分、排行、事件记录。

RSSI 是负数，数字越大代表信号越强：

- `-20 dBm` 比 `-40 dBm` 强。
- `RSSI >= -35 dBm` 表示靠近到足够强。
- `-40 <= RSSI <= -20` 表示保持在一个信号范围内。

## 二、现场开局通用流程

### 1. 启动本地端

双击 `start_config.cmd` 或在 macOS 上运行 `start_config_mac.command`，浏览器打开本地端。

### 2. 连接控制端热点

电脑需要连接控制端 AP。默认控制端地址是：

```text
http://192.168.4.1
```

如果没有连接控制端，设备列表应显示现场设备为 0。本地端不会再用旧缓存假装设备在线。

### 3. 扫描设备

进入“设备”页面或房间预备弹窗，点击扫描。扫描后设备会出现在设备列表中，可以给设备命名，例如：

- 魔杖1
- 魔杖2
- 宝箱1
- 宝箱2

### 4. 设置分组

进入“分组”，把设备放进本局需要的源组和目标组。常见方式：

- 源组：玩家手里的魔杖。
- 目标组：宝箱、据点、目标物。
- 双人玩法：两个玩家也可以分别放入源组和目标组，然后做指定配对。

### 5. 选择玩法预设并创建房间

进入“玩法预设”，从系统默认玩法或我的玩法中创建房间。

玩法预设只是默认规则；房间才是本局真实配置。  
同一个玩法可以创建多个房间，并且每个房间覆盖不同 RSSI、持续时间、计分、冷却和灯效。

### 6. 房间向导

房间向导一般按这个顺序走：

1. 选择玩法预设。
2. 填房间名称和备注。
3. 选择源组和目标组。
4. 覆盖本局 RSSI、持续时间、计分和重复规则。
5. 如果是指定配对玩法，设置设备配对。
6. 设置源组和目标组空闲灯效、触发灯效。
7. 保存房间。

### 7. 设备预备

进入房间，点“设备预备”。预备会：

- 自动结束测试灯效。
- 下发本局规则和灯效。
- 扫描/确认参与设备状态。
- 显示固件指令预览和设备状态。

如果玩法需要指定配对，必须先连接控制端、扫描到源组和目标组设备，并完成每台源设备的目标选择，否则不能进入有效开局。

### 8. 开始游戏

点击“开始游戏”后，本地端和控制端不参与实时判定。  
接收端会自主广播、判断、触发灯效、记录事件。

### 9. 结束游戏

点击“停止游戏”。本地端会汇总当前场次数据并写入历史记录。  
后续可以从历史数据库查看玩家长期表现。

## 三、空闲灯效是什么意思

“空闲灯效”不是游戏外待机，而是本局运行状态下的默认视觉状态。

空闲灯效生效场景：

- 设备已经预备或正在游戏中。
- 还没有触发成功事件。
- 触发灯效播放结束后回到空闲状态。
- 冷却期间如果没有专门冷却灯效，就回到空闲状态。

停止游戏、停止测试、熄灭时，应该关闭 LED，不再保持空闲灯效。

## 四、信号强度指示灯

每个玩法都可以选择开启信号强度指示灯。它适合寻宝、距离保持、共鸣等需要玩家靠近目标的玩法。

字段含义：

- 开关：是否启用。
- LED 路径：选择 LED1/LED2/LED3 其中一路作为指示灯。
- 灯珠总数：默认 10，可按实际灯带长度设置。
- 弱信号：例如 `-90 dBm`，低于这个值基本不亮。
- 强信号：例如 `-35 dBm`，达到或超过时亮满。
- 压缩比例：调整 RSSI 到灯珠数量的曲线。比例越大，强信号区域变化越敏感；比例越小，变化更平滑。

推荐调试办法：

1. 先用信号测试页面看两台设备之间的 RSSI。
2. 把弱信号设为现场远距离时的值，例如 `-85`。
3. 把强信号设为希望触发前的值，例如 `-35`。
4. 如果灯珠一下子从 1 跳到 10，降低压缩比例。
5. 如果靠近了灯珠变化仍不明显，提高压缩比例。

## 五、玩法 1：多人寻宝混战

### 玩法目标

多个玩家拿着魔杖寻找多个目标设备。玩家靠近目标后得分。

### 推荐设备

- 源组：所有玩家魔杖。
- 目标组：所有宝箱或目标物。

### 默认规则

- 底层类型：一次触发计分。
- 匹配方式：源组到目标组。
- RSSI：`>= -35 dBm`。
- 持续时间：`2000 ms`。
- 计分对象：源玩家 +1。
- 重复规则：每对玩家和目标只计一次。

### 为什么不是“每个目标全局只算一次”

当前接收端自主判定的可靠能力是“某个玩家对某个目标只计一次”。  
如果要做到“一个目标被任何玩家发现后全局失效”，需要目标设备统一判定并广播目标失效状态。这个属于后续更强的目标归属玩法，不应在寻宝默认规则里误导主持人。

### 示例

房间：测试1  
源组：魔杖1、魔杖2  
目标组：宝箱1、宝箱2  

魔杖1靠近宝箱1，RSSI 稳定达到 `-32 dBm` 并持续 2 秒：

```text
魔杖1 发现 宝箱1
魔杖1 +1 分
```

魔杖1再次靠近宝箱1不再重复计分。  
魔杖2靠近宝箱1可以计分，因为这是另一对设备。

### 现场注意

- 如果希望目标被发现后彻底不再给任何人得分，应使用或扩展“小组占点/目标判定”类玩法，而不是多人寻宝默认规则。
- 大屏应显示个人排行榜、事件记录和 RSSI。

## 六、玩法 2：单人寻宝

### 玩法目标

一个玩家寻找多个目标，每找到一个目标得分。

### 推荐设备

- 源组：一个玩家魔杖。
- 目标组：一个或多个宝箱。

### 默认规则

- 底层类型：一次触发计分。
- 匹配方式：源组到目标组。
- RSSI：`>= -35 dBm`。
- 持续时间：`2000 ms`。
- 计分对象：源玩家 +1。
- 重复规则：每对设备只计一次。

### 示例

魔杖1依次找到宝箱1、宝箱2：

```text
魔杖1 发现 宝箱1，魔杖1 +1
魔杖1 发现 宝箱2，魔杖1 +1
```

最终魔杖1得 2 分。

### 现场注意

- 适合单人闯关、儿童找宝、NPC 引导测试。
- 如果现场 RSSI 很强但不触发，先把阈值从 `-35` 调到 `-45` 测试。

## 七、玩法 3：双人魔杖共鸣

### 玩法目标

两名玩家保持合适距离或姿态，持续达标后双方得分。

### 推荐设备

- 源组：玩家 A 的魔杖。
- 目标组：玩家 B 的魔杖。
- 配对方式：指定配对。

### 默认规则

- 底层类型：持续达标计分。
- 匹配方式：指定配对。
- RSSI 范围：`-40 <= RSSI <= -20`。
- 触发模式：连续达标。
- 达标时间：`60000 ms`。
- 丢失宽限：`2000 ms`。
- 计分对象：双方玩家 +1。
- 失败处理：离开范围超过宽限后计时清零。

### 示例

魔杖1和魔杖2配对。两人保持在指定范围内 60 秒：

```text
魔杖1 与 魔杖2 共鸣成功
魔杖1 +1
魔杖2 +1
```

如果中途离开范围超过 2 秒，计时重新开始。

### 现场注意

- 这个玩法必须做设备配对。没有扫描到真实设备时不能只靠分组继续。
- RSSI 范围不能写反。`-20` 是强信号端，`-40` 是弱信号端。
- 如果两台设备贴在一起一直不计分，可能 RSSI 高于 `-20`，需要把上限改成 `-10` 或关闭上限。

## 八、玩法 4：小组占点

### 玩法目标

多个玩家或多个小组争夺同一个目标点。目标设备会判断当前最强信号来源，只有当前占领者累计时间。

### 推荐设备

- 源组：参与争夺的玩家或小组魔杖。
- 目标组：据点、宝箱、目标设备。

### 默认规则

- 底层类型：竞争归属计分。
- 匹配方式：源组到目标组。
- RSSI：`>= -45 dBm`。
- 归属策略：目标设备判断当前最强平滑 RSSI。
- 触发模式：累计占领。
- 达标时间：`30000 ms`。
- 计分对象：源小组 +1。
- 冷却：`10000 ms`。

### 示例

红队魔杖和蓝队魔杖同时靠近据点。  
据点看到红队 RSSI 更强，红队累计占领时间。红队保持最强身份累计 30 秒：

```text
红队魔杖 占领 据点1
红队 +1
```

如果蓝队中途变成最强，红队停止累计，蓝队开始累计。

### 现场注意

- 这个玩法由目标设备判定，比寻宝更适合“目标全局归属”。
- 需要保证目标设备在线并在目标组中。
- 如果有多个目标，可以创建多个房间或把多个目标放入目标组，但现场解释要明确每个目标各自判定。

## 九、玩法 5：距离保持

### 玩法目标

玩家或设备保持在指定 RSSI 范围内，按周期或累计达标得分。

### 推荐设备

- 源组：玩家魔杖。
- 目标组：目标设备或另一批玩家魔杖。

### 默认规则

- 底层类型：持续达标计分。
- 匹配方式：任意匹配。
- RSSI 范围：`-55 <= RSSI <= -25`。
- 触发模式：周期计分。
- 周期：`10000 ms`。
- 计分对象：源玩家 +1。
- 重复规则：允许重复。

### 示例

魔杖1和目标设备保持在范围内。每连续保持 10 秒：

```text
魔杖1 完成一次保持计分
魔杖1 +1
```

保持 30 秒可得到 3 分。

### 现场注意

- 大屏应显示“完成保持”或“事件”，不能显示成寻宝发现。
- 如果设备太近导致 RSSI 高于上限 `-25`，也会判定失败。
- 适合护送、保持距离、训练节奏类玩法。

## 十、玩法 6：灯效测试

### 玩法目标

用于验证灯效、设备和信号，不作为正式计分玩法。

### 两种测试方式

1. 设备预备弹窗里的“测试效果”：人工让所有参与设备播放本局触发灯效。
2. 玩法预设里的“灯效测试”：通过 RSSI 触发灯效，但不计分。

### 默认规则

- 底层类型：一次触发。
- RSSI：`>= -25 dBm`。
- 持续时间：`2000 ms`。
- 计分对象：不计分。
- 重复规则：允许重复。

### 现场注意

- 开始游戏或下发预备前，系统应自动停止测试灯效，避免测试状态残留。
- 如果灯还亮着，点击“停止测试/熄灭”。
- 停止测试会执行全灯清除，尽量关闭残留灯珠。

## 十一、静态端到端验收结果

本次按本地端、控制端、接收端三层检查。

### 本地端

- 玩法预设已经分为系统默认玩法和我的玩法。
- 房间保存独立覆盖参数，可以同玩法开多个不同参数房间。
- 发布 payload 使用精简运行态，包含规则、分组、灯效、配对和信号指示灯参数。
- 已修复：控制端 schema v3 状态不再被页面显示逻辑压成 v2。
- 已修复：指定配对玩法如果没有真实源/目标设备或配对不完整，会阻止预备/开始。
- 已修复：距离保持类事件文案不再默认显示成“共鸣成功”。
- 已修复：多人寻宝默认描述和规则改为当前硬件可可靠执行的“每对设备只计一次”。

### 控制端

- 导入后会保存设备、分组、规则、灯效和配对。
- 开始游戏时会下发 `RULE|2`、`METER`、`PAIR`、`CFG`、`TRG`、`START`。
- 收到接收端 `EVT2` 后会记录源设备、目标设备、分组、RSSI、分数和时间。
- `/state` 会返回运行事件和接收端摘要，供本地端大屏显示。

### 接收端

- 开始后自主发送 `BEACON`，并用其他接收端 beacon 的 RSSI 判断。
- 支持一次触发、持续达标、周期计分和竞争归属的基础执行。
- 竞争归属由目标设备判定当前最强 RSSI，并只给当前最强者累计占领时间。
- 支持信号强度指示灯：没信号不亮，有信号按弱/强阈值映射灯珠数量。
- 触发灯效会播放一段时间后恢复空闲灯效，不应无限占用触发状态。

### 当前需要主持人知道的边界

- “每个目标全局只被发现一次”不是多人寻宝默认能力；默认是每对玩家和目标只计一次。
- `once_per_target`、`once_per_source` 这类全局去重语义，在接收端自主判定下需要更多同步机制。默认玩法已避开这个不可靠组合。
- 目标失效、目标锁定属于高级后处理，默认玩法不依赖它。需要全局目标状态时，优先用竞争归属类玩法。
- 真机 RSSI 受遮挡、人体、天线方向和供电影响很大。正式开场前必须用信号测试页确定阈值。

## 十二、常见问题定位

### 看不到设备

1. 确认电脑连接控制端 AP。
2. 点击扫描。
3. 如果仍为 0，看控制端串口是否收到 `PRESENT`。
4. 如果本地端没连接控制端，不应显示旧缓存设备。

### 灯效能测，但游戏不触发

1. 看预备弹窗里的固件指令预览。
2. 确认源组和目标组都选对。
3. 确认设备在对应分组内。
4. 开启信号强度指示灯或信号测试页，看两台设备之间 RSSI 是否达到条件。
5. 如果是指定配对，检查配对表。

### RSSI 明明很强还是不触发

检查是否用了范围规则。  
例如双人共鸣 `-40 <= RSSI <= -20`，如果贴太近达到 `-15`，反而超出范围，不会触发。

### 大屏显示不符合玩法

1. 寻宝应该显示“发现”。
2. 双人共鸣应该显示“共鸣成功”。
3. 小组占点应该显示“占领”。
4. 距离保持应该显示“完成保持”。

如果显示成其他玩法，优先检查房间选择的玩法预设和本局覆盖参数。

### 触发灯效一直不结束

正常行为应该是触发灯效播放一段时间，然后回到空闲灯效。  
如果一直不结束：

1. 点击停止游戏或停止测试/熄灭。
2. 重新下发预备。
3. 确认接收端固件版本是最新包内版本。
