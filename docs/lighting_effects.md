# 灯效系统说明

这份文档只讲一件事：**网页里设置的灯效，不再只是备注文字，而是会被控制端下发到接收端并真正执行的参数**。

## 1. 灯效是怎么流动的

用户在电脑端局域网配置页里修改分组灯效后，页面会生成一段可执行的效果配置。流程如下：

1. 在配置页选择灯效模板。
2. 调整颜色、速度、亮度、周期等参数。
3. 点击“保存本地”或“一键发布”。
4. 配置文件中的 `effect` 字段会保存成机器可读的效果字符串。
5. 控制端收到配置后，会把对应分组的效果通过 ESP-NOW 发给接收端。
6. 接收端收到 `FXSET|...` 后，更新当前运行中的灯效。
7. 当接收端进入 `START` 状态时，就按这个效果真正点亮灯带。

换句话说：

- `备注` 是给人看的
- `effect` 是给设备执行的

## 2. 当前支持的效果模板

现在支持 4 种模板：

### 2.1 自检 `selftest`

用途：
- 设备上电后的默认测试效果
- 用来确认灯带、供电和三路输出是否正常

说明：
- 不需要额外参数
- 默认回退也会使用它

示例：

```text
selftest
```

### 2.2 常亮 `solid`

用途：
- 某个分组需要稳定常亮
- 现场状态灯、固定提示灯

参数：
- 3 路颜色
- 亮度 `0-100`

示例：

```text
solid|F5D76E|7CC5FF|68E0A8|60
```

### 2.3 呼吸 `breath`

用途：
- 适合“魔杖”类缓慢变化的灯效
- 也适合做有节奏的氛围提示

参数：
- 3 路颜色
- 速度 `1-5000`
- 亮度 `0-100`

示例：

```text
breath|F5D76E|7CC5FF|68E0A8|45|100
```

### 2.4 闪烁 `blink`

用途：
- 需要明显提醒的时候
- 点名、确认、提示

参数：
- 3 路颜色
- 周期 `50-20000`
- 占空比 `1-99`
- 亮度 `0-100`

示例：

```text
blink|FFD24D|34B3FF|FFFFFF|500|50|100
```

## 3. 字符串格式

控制端和接收端之间交换的是一段简短字符串，格式如下：

```text
模式|颜色1|颜色2|颜色3|参数A|参数B|参数C
```

说明：

- 颜色使用 6 位十六进制，不带 `#`
- 所有参数都经过网页校验
- 空值或非法值会回退到默认值

## 4. 页面里每个字段的意思

在局域网配置页里，灯效编辑区主要有这些字段：

- `灯效模板`
- `灯1颜色`
- `灯2颜色`
- `灯3颜色`
- `速度`
- `亮度`
- `闪烁周期`
- `占空比`

保存时，页面会自动把这些字段合成 `effect` 字符串。

## 5. 推荐的实际用法

### 魔杖组

建议用：

- 模式：`breath`
- 颜色：偏黄、偏蓝、偏绿
- 亮度：100

这样容易看出状态在变化，也比较适合手持设备。

### 宝箱组

建议用：

- 模式：`solid`
- 颜色：偏暗或低亮度
- 亮度：40-60

这样在被记录、被静默或被点名时更清楚。

### 联调测试

建议用：

- 模式：`blink`
- 周期：500 左右
- 占空比：50

这样最容易确认控制端到接收端的链路是不是通了。

## 6. 常见误区

### 6.1 备注不会驱动灯效

备注只是说明文字。  
真正执行的是 `effect`。

### 6.2 只保存备注，不会有灯效变化

如果只改了备注，没有改灯效模板和参数，那接收端执行的效果不会变。

### 6.3 控制端只是搬运工

控制端负责：

- 接收配置
- 保存配置
- 下发效果
- 执行 START / STOP / 点名 / 扫描

真正的效果逻辑由网页配置页生成，再由控制端转发给接收端。

## 7. 一个完整例子

假设你有一个“魔杖组”：

- 模式：`breath`
- 颜色：黄 / 蓝 / 绿
- 亮度：100
- 速度：45

网页生成的效果字符串可能是：

```text
breath|F5D76E|7CC5FF|68E0A8|45|100
```

控制端保存后，会把这串效果发给对应接收端。  
接收端只要收到 `START`，就按这条规则进入实际灯效。
