# 局域网配置页使用说明

这份说明面向现场同事和后续接手的人。目标很简单：不用理解 JSON，也不用理解代码，只要会点按钮就能完成配置。

## 1. 这个系统分成哪三部分

### 控制端

控制端是现场盒子。它负责：

- 开 Wi-Fi AP
- 扫描设备
- 给设备点名
- 给设备改名
- 显示当前配置和运行状态
- 接收电脑端发来的最终配置

### 电脑端局域网配置页

这是主要编辑器。它负责：

- 读取控制端当前状态
- 编辑设备名称
- 建立和修改分组
- 设定分组之间的关系
- 保存到电脑本地
- 一键发布到控制端

### 本地配置文件

电脑会保存一份最新配置文件：

- `magic_wand_config.json`

这个文件是“当前唯一版本”。再次保存时会覆盖旧版本。

## 2. 两种工作模式

### 联机模式

适合现场操作。

步骤：

1. 电脑连接到控制端 Wi-Fi。
2. 双击 `D:\MagicProject\lan_config\serve.ps1`。
3. 浏览器自动打开配置页。
4. 点击“从控制端读取”。
5. 编辑后点击“保存现有配置”或“一键发布”。

### 离线模式

适合控制端暂时不在线、但你想先整理规则。

步骤：

1. 直接打开 `file:///D:/MagicProject/lan_config/index.html`。
2. 点击“读取本地配置”选择已有 JSON。
3. 如果没有本地文件，就直接新建分组和编辑。
4. 点击“保存现有配置”导出最新 JSON。
5. 等控制端恢复后，再用“一键发布”上传。

## 3. 页面上的每个按钮是干什么的

### 从控制端读取

把控制端当前状态拉到电脑里。

适合场景：

- 现场已经有人配置过
- 你想先看现状，再继续改

### 读取本地配置

从电脑上的本地 JSON 文件读取配置。

适合场景：

- 控制端暂时不可达
- 你想接着上次的配置继续改

### 保存现有配置

把当前页面的内容保存成最新本地配置。

联机模式下：

- 直接写入 `lan_config` 同级文件夹中的 `magic_wand_config.json`

离线模式下：

- 下载一个 JSON 文件，手动保存为同名文件即可

### 恢复草稿

恢复浏览器自动保存的草稿。

适合场景：

- 刷新页面后还没发布
- 临时关掉浏览器后又想接着改

### 清除草稿

删除浏览器里的自动草稿。

适合场景：

- 想从本地配置文件重新开始
- 想丢掉临时改动

### 新建分组

创建一个新的有效分组。

注意：

- 页面只显示已启用分组
- 不会先摆一堆空分组让人误会

### 扫描设备

向控制端发送扫描命令，刷新设备列表。

适合场景：

- 新设备刚上电
- 想重新确认现场有哪些模块

### 一键发布

把当前页面的完整配置上传到控制端并保存。

适合场景：

- 规则已经整理完
- 现场要执行新配置

### 导出 JSON

把当前配置显示成 JSON 预览，方便检查。

## 4. 设备卡片怎么看

每个设备卡片会显示：

- 设备编号
- 设备名称
- MAC 地址
- 当前信号强度
- 最近一次响应时间
- 设备已经属于哪些分组

设备卡片上可以做这些事：

- 改设备名称
- 勾选它属于哪些分组
- 点名测试
- 保存设备改动

## 5. 分组卡片怎么看

每个分组卡片会显示：

- 分组编号
- 分组名称
- 备注
- 成员数量
- 行为模式
- 对接目标分组

分组卡片里可以设置：

- 分组名称
- 分组备注
- 目标分组
- 共享型 / 独立型
- RSSI 阈值
- 保持时间
- 效果说明
- 静默说明

### 共享型

同一组内成员共享一套行为，不按成员单独记录。

### 独立型

同一组内每个成员单独记录，适合“每个魔杖自己记自己的进度”。

## 6. 推荐操作顺序

1. 连接控制端 Wi-Fi。
2. 打开配置页。
3. 从控制端读取。
4. 检查设备列表。
5. 给设备改名。
6. 建立分组。
7. 给设备分配分组。
8. 设置分组关系。
9. 保存现有配置到电脑。
10. 一键发布到控制端。

## 7. 如果控制端连不上怎么办

你会看到“读取失败”之类的提示。此时不要慌，直接切到离线模式继续编辑。

你仍然可以：

- 建分组
- 改名字
- 调关系
- 保存到电脑

等控制端恢复后，再执行“一键发布”。

## 8. 现在这套方案的边界

- 控制端只保留现场动作和运行状态。
- 复杂编辑放电脑端。
- 本地保存是唯一的电脑备份。
- 规则变化时，优先改电脑端，不要把复杂逻辑重新塞回 ESP32 页面。
