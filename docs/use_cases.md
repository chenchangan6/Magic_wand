# 使用用例

这份文档用几个真实场景，帮助理解“分组、点名、保存、发布”到底怎么配合。

## 用例 1：魔杖组和宝箱组

这是最典型的测试场景。

### 目标

- `魔杖组` 负责发起感应和记录进度
- `宝箱组` 负责被寻找和被识别

### 设定

- 建立分组 `魔杖组`
- 建立分组 `宝箱组`
- 把一些设备加入 `魔杖组`
- 把一些设备加入 `宝箱组`
- 设置 `魔杖组 -> 宝箱组`
- 把 `魔杖组` 设成 `独立型`
- 把 `宝箱组` 设成 `共享型`

### 用户行为

当某个魔杖靠近某个宝箱时：

- 系统记录一次 `魔杖A -> 宝箱3`
- 同一个魔杖再次碰到同一个宝箱，不重复计数
- 另一根魔杖之后仍然可以独立记录同一个宝箱

### 页面表现

- 魔杖自己的进度灯按发现数累计
- 宝箱组仍作为统一目标存在
- 记录里能看到“谁发现了谁”

## 用例 2：同一设备属于多个分组

### 目标

一个模块可以同时承担多个角色。

### 设定

- 设备 `A` 既属于 `魔杖组`
- 也属于 `测试组`

### 结果

- 页面上它会显示多个分组标签
- 分组关系编辑时仍然可以单独控制它的归属
- 保存后不会覆盖掉其他分组成员身份

## 用例 3：现场只看不改

### 目标

让现场同事拿手机只看状态，不随便改复杂规则。

### 设定

- 控制端开 AP
- 手机连入控制端
- 打开控制端的 192.168.4.1 页面

### 结果

- 可以看到当前状态
- 可以点名
- 可以做简单扫描
- 不需要进入电脑端做复杂编辑

## 用例 4：控制端临时不在线

### 目标

控制端没连上时，不影响整理规则。

### 设定

- 电脑打不开控制端
- 或者现场信号还没接好

### 结果

- 页面提示读取失败
- 用户切换到离线编辑
- 先在电脑上改好
- 之后再发布

## 用例 5：保存和恢复

### 目标

保证规则不会因为浏览器刷新而丢失。

### 设定

- 用户编辑了多个分组
- 还没来得及发布

### 结果

- 页面自动保存草稿
- 刷新后可以恢复草稿
- 也可以直接读取本地 JSON 继续编辑

## 用例 6：分组模板快速套用

### 目标

给同事一个更快的起步方式。

### 设定

- 新建一个分组
- 从“规则模板”里选择 `源组模板`、`目标组模板` 或 `测试模板`

### 结果

- 名称、备注、目标、模式、阈值、保持时间会自动填好
- 用户只需要微调即可

## 用例 7：推荐的现场操作顺序

1. 打开控制端。
2. 电脑连接控制端 Wi-Fi。
3. 打开配置页。
4. 从控制端读取。
5. 扫描设备。
6. 给设备改名。
7. 建分组。
8. 配关系。
9. 保存本地。
10. 一键发布。
