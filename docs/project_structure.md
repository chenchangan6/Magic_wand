# 项目结构

这个项目现在分成四个主要部分。

## `firmware/receiver`

接收端固件。

职责：

- 接收 ESP-NOW 命令
- 控制 LED 效果
- 响应 START / STOP
- 响应点名测试
- 作为现场“动作执行端”

当前状态：

- 已经能正常烧录
- 保留了当前稳定的 3 路 LED 测试方案
- 后续会继续扩展到完整的硬件灯路

## `firmware/controller`

控制端固件。

职责：

- 开 Wi-Fi AP
- 提供现场用的轻量网页
- 扫描设备
- 点名设备
- 重命名设备
- 导入最终配置
- 保存运行时状态

控制端不再承担复杂编辑器的长期增长压力。

## `lan_config`

电脑端局域网配置页。

职责：

- 读取控制端现状
- 离线编辑
- 电脑本地保存
- 一键发布到控制端
- 作为复杂规则的主编辑器

这是给人用的主要工作台。

## `docs`

说明文档目录。

建议优先阅读顺序：

1. `README.md`
2. `docs/user_guide.md`
3. `docs/use_cases.md`
4. `docs/config_flow.md`
5. `docs/local_config_page.md`

## `archive`

历史参考文件目录。

这里放：

- 已经过时但还想保留的代码片段
- 临时参考文件
- 不参与编译的备份材料

## 设计原则

- 复杂规则放电脑端
- 控制端只做执行和快速查看
- 电脑上保留唯一的本地配置文件
- 现场需要的动作必须手机也能完成
