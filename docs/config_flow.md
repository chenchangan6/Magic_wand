# 配置流转说明

这份文档解释“数据从哪里来、到哪里去、谁负责什么”。

## 1. 核心思路

系统只有一条主线：

**电脑端编辑 -> 本地保存 -> 一键发布 -> 控制端保存执行**

控制端不是复杂编辑器，它只是现场执行盒。

## 2. 三个层次

### 2.1 设备层

设备层包含：

- 接收端 ESP32-C6 模块
- 控制端 ESP32-C6 模块

设备层负责真实硬件动作。

### 2.2 配置层

配置层包含：

- 设备名称
- 分组
- 分组关系
- 行为模式
- 灯效说明
- 发现记录

配置层优先在电脑端完成编辑。

### 2.3 保存层

保存层包含两份：

- 电脑上的 `magic_wand_config.json`
- 控制端内部保存的运行配置

## 3. 标准流程

### 3.1 读取现场状态

1. 电脑连接控制端 Wi-Fi。
2. 打开局域网配置页。
3. 点击“从控制端读取”。
4. 页面拿到设备和分组的当前状态。

### 3.2 编辑

用户在电脑端修改：

- 设备名称
- 设备归属分组
- 分组名称
- 分组目标
- 独立型 / 共享型
- 灯效说明
- 静默说明

### 3.3 本地保存

点击“保存现有配置”后：

- 联机时，配置会直接写入电脑同级文件夹
- 离线时，浏览器会下载 JSON 文件

默认文件名：

- `magic_wand_config.json`

### 3.4 发布

点击“一键发布”后：

1. 页面生成当前完整 JSON
2. 通过 Wi-Fi 发给控制端
3. 控制端校验格式
4. 控制端保存到自己的 NVS
5. 控制端恢复运行状态

## 4. 控制端保留什么

控制端只保留必要内容：

- 当前设备列表
- 当前分组状态
- 简单的扫描和点名
- 状态查看
- 配置导入

## 5. 电脑端保留什么

电脑端保留：

- 复杂编辑能力
- 本地备份
- 离线编辑能力
- 人类可理解的界面

## 6. 为什么这样分

因为 ESP32 的空间有限，而且页面越长越难维护。

把复杂逻辑放到电脑端以后：

- 控制端更稳
- 页面更好改
- 规则更容易理解
- 后续扩展不会反复推翻前面的工作

## 7. 当控制端不可达时

如果控制端暂时连不上：

- 电脑端仍然能编辑
- 可以读取本地配置
- 可以保存最新版本
- 等控制端恢复后再发布

这保证现场不会因为链路问题卡死。
